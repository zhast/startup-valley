# Deferred public demo deployment

Public hosting is deferred at the user's request. No live anonymous demo URL has been verified, and no deployment workflow is installed. The tested configuration is retained as [public-demo.workflow.yml.example](public-demo.workflow.yml.example) for future work; committing this example does not run or publish anything.

If hosting is requested later, deliberately install the example as `.github/workflows/public-demo.yml` and configure GitHub Pages before enabling publication. Once installed, it builds the existing release export and deploys `dist/` on pushes to `main`, or when started manually from `main`. Confirm the successful deployment result and anonymous HTTPS asset checks before sharing a public URL.

The example pins Node 22.19.0, the existing Godot 4.7.2 editor, its official Linux archive SHA256, and every GitHub action to a verified commit. Its YAML and shell blocks were parsed locally, and the export-tool suite passed 48 tests; the hosted workflow itself has not run. When installed, it installs both lockfiles, runs the offline harness tests and export-tool tests, downloads only the matching web templates through `setup:web`, then runs the release asset gate, export validation, and Godot validation/tests. No provider credentials or paid API calls are required.

The normal export remains unchanged. The checked build is about 68.9 MB: its largest files are a 39,514,754-byte WASM and a 29,103,004-byte PCK. Both fit GitHub Pages' [1 GB published-site limit](https://docs.github.com/en/pages/getting-started-with-github-pages/github-pages-limits). The loaders use relative URLs, including the browser Worker, so the project-site path is supported. The single-threaded Godot export and SQLite OPFS SAH pool do not require custom COOP/COEP headers; Pages does not interpret the optional `_headers` file.

The [official Pages workflow](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages) requires `pages: write`, `id-token: write`, and the `github-pages` environment. These permissions are limited to the deploy job. The build artifact remains available even if repository hosting permissions prevent deployment.

`configure-pages` attempts initial enablement. Its [pinned input contract](https://github.com/actions/configure-pages/blob/983d7736d9b0ae728b81ab479565c72886d7745b/action.yml) states that creating a Pages site requires a credential other than `GITHUB_TOKEN` (for a GitHub App, administration and Pages write permissions). If GitHub rejects creation, a repository administrator must enable **Settings → Pages → Source: GitHub Actions**, then rerun the deploy job. Do not report the demo as public until the deployment succeeds and anonymous HTTPS requests retrieve its HTML, JavaScript, WASM, PCK, and browser runtime successfully.

Sites was evaluated but its available access modes in this workspace do not include anonymous public access. Its underlying static-asset [25 MiB file limit](https://developers.cloudflare.com/workers/platform/limits/) would also require packaging changes: gzip reduces this WASM to 10,153,810 bytes, but the PCK remains 28,131,786 bytes. The explored Worker/chunk prototype is not part of the retained deployment example.
